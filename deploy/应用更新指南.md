# 应用更新指南（重新打包上传）

适用于：已在 ECS 部署过，现在要更新后端或前端，需要**停服务 → 备份旧版本 → 删旧文件 → 上传新包 → 启服务**。
sudo systemctl stop reportweb
BACKUP_DIR=/opt/reportweb/backup/$(date +%Y%m%d-%H%M)
mkdir -p "$BACKUP_DIR"
cp /opt/reportweb/report-web-0.0.1-SNAPSHOT.jar "$BACKUP_DIR/" 2>/dev/null || true
cd /opt/reportweb && zip -r "$BACKUP_DIR/www.zip" www/
cp -r /opt/reportweb/www "$BACKUP_DIR/www"
ls -la "$BACKUP_DIR"
rm -f /opt/reportweb/report-web-0.0.1-SNAPSHOT.jar
rm -rf /opt/reportweb/www/*
ls -la /opt/reportweb/www/
---
cd /opt/reportweb && unzip -o dist.zip -d www
ls -la /opt/reportweb/www/
sudo systemctl start reportweb
sudo systemctl status reportweb


## 一、本机准备（Windows）

1. **打包后端**（项目根目录）  
   运行 **`deploy\仅打包不上传.bat`**，得到：
   - `target\report-web-0.0.1-SNAPSHOT.jar`

2. **打包前端**  
   运行 **`deploy\打包前端为zip.bat`**，得到：
   - `deploy\dist.zip`

3. 将 **jar** 和 **dist.zip** 上传到 ECS（见下文）。

---

## 二、ECS 上操作（按顺序执行）

以下命令在 **阿里云 ECS Workbench 终端**（或 SSH）中执行，且假设应用目录为 **`/opt/reportweb`**（与《ECS完整部署步骤》一致）。

### 步骤 1：停止后端服务

```bash
sudo systemctl stop reportweb
```

确认已停止：

```bash
sudo systemctl status reportweb
```

应显示 **inactive (dead)**。

---

### 步骤 2：建备份文件夹并备份旧版本

先建一个带日期的备份目录，再把当前运行的 jar 和前端整体拷进去，方便回滚：

```bash
# 备份目录：/opt/reportweb/backup/日期时间，例如 backup/20260203-1430
BACKUP_DIR=/opt/reportweb/backup/$(date +%Y%m%d-%H%M)
mkdir -p "$BACKUP_DIR"
```

**备份旧后端 jar：**

```bash
cp /opt/reportweb/report-web-0.0.1-SNAPSHOT.jar "$BACKUP_DIR/" 2>/dev/null || true
```

**备份旧前端（整个 www 目录打包成 zip）：**

```bash
cd /opt/reportweb && zip -r "$BACKUP_DIR/www.zip" www/
```

若服务器没有 `zip`，可先安装再执行上面命令，或只拷贝目录：

```bash
cp -r /opt/reportweb/www "$BACKUP_DIR/www"
```

查看备份是否生成：

```bash
ls -la "$BACKUP_DIR"
```

应有 `report-web-0.0.1-SNAPSHOT.jar`（若存在）和 `www.zip` 或 `www/`。

---

### 步骤 3：删除旧后端 jar

```bash
rm -f /opt/reportweb/report-web-0.0.1-SNAPSHOT.jar
```

---

### 步骤 4：删除旧前端文件（必须）

保证新前端解压后没有残留旧文件：

```bash
rm -rf /opt/reportweb/www/*
```

检查是否清空：

```bash
ls -la /opt/reportweb/www/
```

应为空或仅剩隐藏文件。

---

### 步骤 5：上传新文件到 ECS

在**本机**用 **Workbench 上传**（或 scp）到 **`/opt/reportweb/`**：

| 本机文件 | 上传到 ECS |
|----------|------------|
| `target\report-web-0.0.1-SNAPSHOT.jar` | `/opt/reportweb/` |
| `deploy\dist.zip` | `/opt/reportweb/` |

---

### 步骤 6：解压新前端到 www

在 **ECS 终端**执行：

```bash
cd /opt/reportweb && unzip -o dist.zip -d www
```

若习惯解压后删 zip：

```bash
cd /opt/reportweb && unzip -o dist.zip -d www && rm -f dist.zip
```

确认有 `index.html` 和 `assets/`：

```bash
ls -la /opt/reportweb/www/
```

---

### 步骤 7：启动后端服务

```bash
sudo systemctl start reportweb
```

查看状态：

```bash
sudo systemctl status reportweb
```

应为 **active (running)**。若有报错可看日志：

```bash
journalctl -u reportweb -n 50 --no-pager
```

---

### 步骤 8：验证

1. 浏览器访问 **http://你的ECS公网IP**，应能打开登录页。
2. 登录后确认功能、数据是否正常（如数据管理、电厂编辑等）。

**若你刚更新了前端，但感觉仍像旧版（项目列表卡顿、仍弹「资源不存在」等），多半是浏览器或中间层缓存了旧 JS：**

1. 用 **强制刷新**：Windows / Linux 上 **Ctrl + F5**，或 Mac 上 **Command + Shift + R**；也可开 **无痕/隐私窗口** 再访问。
2. 在开发者工具 **Network** 中看 `index-*.js`：每次发版打出来的 **文件名中的 hash 应变化**；若与旧版相同，说明 `www` 未真正换成新包，请重查是否已执行 **删空 `www` 再解压 `dist.zip`**（见步骤 4、6）。
3. 项目数很多时，列表会为每个项目请求「总报告任务」状态；数据库 **`reportweb` 用户若无新表权限**会导致接口 **500**，叠加后会卡顿——参见《数据库增量更新流程》中的 **`GRANT`** 说明。

---

## 三、只更新前端或只更新后端

- **只更新前端**：执行 **步骤 1（停服务）→ 步骤 2（备份，可选）→ 步骤 4（删 www）→ 步骤 5（只上传 dist.zip）→ 步骤 6（解压）→ 步骤 7（启服务）**。
- **只更新后端**：执行 **步骤 1 → 步骤 2（备份，可选）→ 步骤 3（删 jar）→ 步骤 5（只上传 jar）→ 步骤 7**，不必动 `www` 和 dist.zip。

---

## 四、命令速查（复制整段执行）

**全量更新（含备份旧版本）：**

```bash
# 1. 停服务
sudo systemctl stop reportweb

# 2. 建备份文件夹并备份旧版本
BACKUP_DIR=/opt/reportweb/backup/$(date +%Y%m%d-%H%M)
mkdir -p "$BACKUP_DIR"
cp /opt/reportweb/report-web-0.0.1-SNAPSHOT.jar "$BACKUP_DIR/" 2>/dev/null || true
cd /opt/reportweb && zip -r "$BACKUP_DIR/www.zip" www/ 2>/dev/null || cp -r www "$BACKUP_DIR/"
ls -la "$BACKUP_DIR"

# 3. 删旧 jar
rm -f /opt/reportweb/report-web-0.0.1-SNAPSHOT.jar

# 4. 删旧前端
rm -rf /opt/reportweb/www/*

# 5. 上传 jar 和 dist.zip 到 /opt/reportweb/ 后，在 ECS 执行下面两行：

# 6. 解压前端
cd /opt/reportweb && unzip -o dist.zip -d www && rm -f dist.zip

# 7. 启服务
sudo systemctl start reportweb
sudo systemctl status reportweb
```

上传文件需在本机用 Workbench 或 scp 完成，**步骤 6、7 必须在 ECS 上传完成后执行**。

## 五、备份目录说明

- 备份根目录：**`/opt/reportweb/backup/`**
- 每次备份一个子目录：**`YYYYMMDD-HHMM`**（例如 `20260203-1430`），便于保留多份历史版本。
- 每个备份目录内通常包含：
  - `report-web-0.0.1-SNAPSHOT.jar`（当时在用的后端包）
  - `www.zip` 或 `www/`（当时的前端文件）
- 若新版本有问题，可从对应备份目录把 jar 拷回 `/opt/reportweb/`、把 www 解压或拷回 `/opt/reportweb/www/`，再重启服务即可回滚。

## 六、Word 导出失败（浏览器提示超时、网络错误；或总报告正常仅第三方失败）

Word 在**服务端整份生成完成后**才开始下载，耗时与报告数量、**附图数量与分辨率**、CPU、内存有关。**第三方单项**常比总报告更「重」，易出现超大 docx、生成与下载都很久。

1. **前端超时**  
   全局 axios 默认 30s。项目总报告、第三方报告、检测通知单 Word 在 `frontend/src/services/projectService.ts` 中已单独设为 **60 分钟（3600s）** 级别超时，以覆盖附图很多、可能超过半小时的第三方报告；部署后务必更新前端 `www`。若仍不够，可再调大该文件中的 `WORD_EXPORT_TIMEOUT_MS`。

2. **Nginx / 网关超时（须与前端对齐）**  
   反代默认 `proxy_read_timeout` 多为 **60s**，远小于超大 Word 的生成时间。你当前若已设为 `300s` 或 `1800s`，在**极重**的第三方报告上仍可能被掐断，建议至少 **`proxy_read_timeout` / `proxy_send_timeout` 不低于 3600s（60 分钟）**，与前端 `WORD_EXPORT_TIMEOUT_MS` 一致；修改后执行 `sudo nginx -t && sudo systemctl reload nginx`：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080/api/;
    proxy_http_version 1.1;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    proxy_connect_timeout 120s;
    client_max_body_size 55m;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    # 超大响应体时，可适当加大缓冲（按需启用）
    # proxy_buffering on;
    # proxy_buffer_size 128k;
    # proxy_buffers 16 512k;
}
```

若前面还有 **SLB / CDN / WAF**，同样要检查其**空闲超时、回源超时**，否则会先于 Nginx 断开。

3. **后端与 JVM**  
   「生成总报告 / 第三方报告 / 检测通知单 Word」接口已**去掉**方法级 `@Transactional`，避免整段 Word 生成长时间占用数据库连接。若日志中出现 **`OutOfMemoryError`**，需在 systemd 或启动脚本中为 jar 增加堆内存（如 `-Xmx2g` 或更高），再观察。

4. **仍失败时**  
   在 ECS 执行：`journalctl -u reportweb -n 200 --no-pager`，查看是否有 `IllegalArgumentException`（例如「当前项目没有需要第三方样式的单项报告」）或其它异常堆栈。

## 七、异步 Word 导出（任务 + 下载）

为避免浏览器长连接等待过久，系统已新增「提交导出任务 -> 后台生成 -> 完成后下载」流程，覆盖总报告、第三方报告、检测通知单三类。

1. **后端新增任务表（必须执行 migration）**
   - 新增脚本：`migrations/V20260429_word_export_job.sql`
   - 若服务器未执行该 SQL，任务接口会报错。

2. **任务文件落盘目录**
   - 生成文件保存到：`${file.upload-dir}/word-export-jobs/`
   - 生产默认即 `/opt/reportweb/uploads/word-export-jobs/`，请确保目录可写。

3. **自动清理**
   - 默认每天凌晨清理过期任务与文件（保留 7 天）
   - 配置项（`application*.yml`）：
     - `app.word-export-job.retention-days`
     - `app.word-export-job.cleanup-cron`
