# 数据库增量更新流程

适用于：**ECS 裸机安装 PostgreSQL**、业务库名为 **`reportweb`** 的场景。  
原则：**不覆盖整库**，只执行 `ALTER` 等增量脚本，保留线上原有数据。

---

## 一、发版顺序（建议）

1. **备份数据库**（快照或 `pg_dump`）
2. **执行迁移 SQL**（加列、改结构等）
3. **验证**表结构
4. **部署后端**（代码依赖新列时必须先完成第 2 步）
5. **部署前端**（若有界面变更）

---

## 二、连接数据库（在 ECS 上操作）

```bash
# SSH 登录 ECS 后，任选其一（按实际账号调整）

sudo -u postgres psql -d reportweb

# 或使用应用账号
psql -h 127.0.0.1 -p 5432 -U reportweb -d reportweb
```

查看有哪些库：

```sql
\l
```

---

## 三、执行 SQL 时注意

- 提示符为 **`reportweb=#`**：可正常输入 SQL。
- 提示符为 **`reportweb-#`**：表示**上一句未结束**（常见是**少了英文分号 `;`**）。可先按 **`Ctrl + C`** 取消，再重新输入。
- **每条 SQL 必须以 `;` 结尾**。
- **不要**在 `psql` 里执行 Shell 命令（如 `sudo ...`）；`sudo` 只在 SSH 终端里用。
- 退出 `psql`：输入 **`\q`**（带反斜杠），不要只输入 `q`。

---

## 四、示例：第三方项目编号列

迁移脚本位置：`migrations/add_third_party_project_number.sql`。

在 `psql` 中执行：

```sql
ALTER TABLE public.projects
    ADD COLUMN IF NOT EXISTS third_party_project_number character varying(100);
```

验证：

```sql
\d public.projects
```

确认存在 `third_party_project_number` 列后，执行 `\q` 退出。

### 第三方名称列

迁移脚本位置：`migrations/add_third_party_name.sql`。

```sql
ALTER TABLE public.projects
    ADD COLUMN IF NOT EXISTS third_party_name character varying(200);
```

验证：`\d public.projects` 中应存在 `third_party_name` 列。

### 项目报告附图表

迁移脚本位置：`migrations/V20260526_project_image_attachments.sql`。

```sql
CREATE TABLE IF NOT EXISTS public.project_image_attachments (
    id SERIAL PRIMARY KEY,
    project_id INTEGER NOT NULL,
    image_urls TEXT NOT NULL,
    description VARCHAR(500),
    display_order INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT now(),
    updated_at TIMESTAMP NOT NULL DEFAULT now()
);
```

验证：`\d public.project_image_attachments` 可看到 `project_id/image_urls/display_order` 等字段。

## 五、新建库 vs 已有库

| 场景 | 做法 |
|------|------|
| **全新空库** | 可使用仓库根目录完整 `reportweb.sql` 初始化 |
| **已有线上数据** | **仅**执行 `deploy/migrations/` 下对应增量脚本，**不要**用完整 SQL 覆盖导入 |

---

## 六、回滚说明

`ADD COLUMN IF NOT EXISTS` 一般**不回滚列**（除非业务明确要求删列）。若需删除该列（谨慎，先备份）：

```sql
ALTER TABLE public.projects DROP COLUMN IF EXISTS third_party_project_number;
ALTER TABLE public.projects DROP COLUMN IF EXISTS third_party_name;
```

---

## 七、应用账号与表权限（重要）

线上 Spring 使用 **`env.sh` 中的 `DB_USERNAME`**（常见为 **`reportweb`**）连接数据库。若增量脚本由 **`postgres`**（或其它超级用户）执行 **`CREATE TABLE`**，新建表默认 **仅 owner 有权限**，应用账号会出现 **`permission denied for table ...`**，接口返回 **500**，前端项目列表可能出现大量失败请求。

**迁移执行后**（在 `psql` 中，以 `postgres` 或有授权权的账号），给应用用户授权，例如表名为 `word_export_job`：

```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.word_export_job TO reportweb;
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLE public.project_image_attachments TO reportweb;
```

若希望以后 **`postgres` 在 `public` 下新建表** 时应用账号自动获得 DML 权限，可执行（按实际 owner 与角色名调整）：

```sql
ALTER DEFAULT PRIVILEGES FOR ROLE postgres IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO reportweb;
```

验证：`\dp public.表名` 中应能看到 `reportweb` 的权限。

## 八、项目报告变更审计表（`project_report_change_log`）

迁移脚本：`migrations/V20260602_project_report_change_log.sql`（建表与 `GRANT` 已写在脚本末尾）。

在 `psql` 中执行（可用 postgres 超级用户，或确认 `reportweb` 有权限）：

```bash
sudo -u postgres psql -d reportweb -f /opt/reportweb/migrations/V20260602_project_report_change_log.sql
```

若脚本未上传到 ECS，可将文件内容复制进 `psql` 执行。

验证：

```sql
\d public.project_report_change_log
```

发版后：打开项目详情 → **报告变更记录** Tab；新建/删除一条报告应出现对应记录；删除后历史仍保留。

---

## 九、发版后浏览器验证（可选）

数据库或权限变更后，建议在浏览器 **开发者工具 → Network** 中确认：

- 打开 **项目列表**，对多个项目的 `GET .../word-export-jobs/latest?type=SUMMARY` 应为 **200**（有任务）或 **404**（无最新任务），不应出现 **批量 500**。
- 若仍见 **500**，对照后端日志与 `\dp` 检查是否漏授权。

---

## 十、检查清单（可复制）

- [ ] 已备份数据库
- [ ] 已在 `reportweb` 库执行迁移 SQL 并以 `;` 结束
- [ ] `\d` 或查询 `information_schema` 已确认结构
- [ ] **若以 postgres 建表、应用用户为 reportweb**：已对新建表执行 `GRANT`（或已配置 `ALTER DEFAULT PRIVILEGES`）
- [ ] 已部署匹配的后端版本
- [ ] 已部署匹配的前端版本（如有）
- [ ] （可选）浏览器 Network 确认 `word-export-jobs/latest` 无批量 500
